## 2. R-09 – Reset Token Exposure

### Trạng thái trước

`AuthService.forgotPassword()` trước đây có logic `demoMode`:
- Khi `MAIL_HOST` trống, trả về `ForgotPasswordResponse` chứa `demoEmail` với `bodyHtml` gồm reset token đầy đủ.
- Người dùng (hoặc attacker) có thể lấy token trực tiếp từ API response thay vì nhận qua email.

### Thay đổi đã thực hiện

**`AuthService.java`** – Logic mới:
```java
public ForgotPasswordResponse forgotPassword(String email) {
    var opt = users.findByEmail(email);
    if (opt.isPresent()) {
        // Lưu token vào DB
        // Nếu emails != null: gửi email thật
        // Nếu SMTP fail: log warning, không throw, không trả token
    }
    // Luôn trả cùng một message, dù email tồn tại hay không
    return new ForgotPasswordResponse("Neu email ton tai trong he thong, ...");
}
```

**`AuthDtos.java`** – `ForgotPasswordResponse` chỉ còn 1 field:
```java
public record ForgotPasswordResponse(String message) {}
// EmailPreview và demoEmail đã bị xóa
```

## 3. R-02a – ADMIN_PASSWORD Fallback

### Vấn đề

`application.properties` dòng 24:
```properties
# Trước
app.admin.password=${ADMIN_PASSWORD:Admin@123}
```
Nếu `.env` trên VPS thiếu `ADMIN_PASSWORD`, Spring Boot dùng `Admin@123` làm mật khẩu admin — đây là mật khẩu yếu, dễ đoán.

### Giải pháp: Spring Profile `prod`

**`application-prod.properties`** (file mới):
```properties
app.admin.password=${ADMIN_PASSWORD}
```
Không có fallback. Khi `SPRING_PROFILES_ACTIVE=prod`:
- Nếu `ADMIN_PASSWORD` bị thiếu → Spring Boot không thể bind `AdminProperties` → `BindException` → **fail-fast** khi startup.
- Nếu `ADMIN_PASSWORD` đủ nhưng ngắn hơn 6 ký tự → `@Size(min=6)` trên `AdminProperties` → `BindValidationException` → **fail-fast**.

**`docker-compose.prod.yml`** (cập nhật):
```yaml
environment:
  SPRING_PROFILES_ACTIVE: prod   # Kích hoạt application-prod.properties
  ADMIN_PASSWORD: ${ADMIN_PASSWORD}  # Không có fallback (đã có từ trước)
```

### Môi trường dev/test không bị ảnh hưởng

- Không set `SPRING_PROFILES_ACTIVE=prod` trong test → `application-prod.properties` không được load.
- `application.properties` vẫn có `${ADMIN_PASSWORD:Admin@123}` → dev và H2 test tiếp tục hoạt động.

## 4. R-02b – JWT_SECRET Fallback Dev

### Vấn đề

`application.properties` dòng 16:
```properties
# Trước
app.jwt.secret=${JWT_SECRET:dev-only-secret-change-me-dev-only-secret-change-me}
```
Dev secret dài 50 ký tự, vượt min=32, nên app vẫn start được ngay cả khi không set `JWT_SECRET`.

### Giải pháp: Spring Profile `prod`

**`application-prod.properties`**:
```properties
app.jwt.secret=${JWT_SECRET}
```
Không có fallback. Khi `SPRING_PROFILES_ACTIVE=prod`:
- `JWT_SECRET` bị thiếu → `BindException` → fail-fast.
- `JWT_SECRET` ngắn hơn 32 ký tự → `@Size(min=32)` trên `JwtProperties` → `BindValidationException` → fail-fast.

**`docker-compose.prod.yml`**:
```yaml
JWT_SECRET: ${JWT_SECRET}  # Không có fallback (đã có từ trước)
```

Việc thêm `SPRING_PROFILES_ACTIVE=prod` đảm bảo cả `JWT_SECRET` và `ADMIN_PASSWORD` đều được kiểm tra nghiêm ngặt khi deploy production.

## 5. R-07 – Error Message Disclosure

### Vấn đề

`application.properties` dòng 35 (trước):
```properties
server.error.include-message=always
```
Mọi exception chưa xử lý đều trả message gốc về client.

### Thay đổi

```properties
# Sau (đã được set trong commit hiện tại)
server.error.include-message=never
```

`ApiExceptionHandler.other()` xử lý tất cả exception chưa được bắt:
```java
@ExceptionHandler(Exception.class)
ResponseEntity<Map<String, String>> other(Exception e) {
    log.error("Loi khong mong doi", e);  // Log đầy đủ cho debug
    return body(HttpStatus.INTERNAL_SERVER_ERROR, "Loi he thong, vui long thu lai");
    // Client chỉ nhận "Loi he thong" – không leak SQL/stack trace
}
```

## 9. Rủi ro khi triển khai production

| Rủi ro | Mức độ | Mô tả |
|--------|--------|-------|
| VPS `.env` thiếu `ADMIN_PASSWORD` hoặc `JWT_SECRET` | 🔴 Cao | Backend sẽ từ chối khởi động với `SPRING_PROFILES_ACTIVE=prod` — đây là behavior đúng (fail-fast), nhưng cần đảm bảo `.env` đã được cập nhật trước khi deploy |
| `ADMIN_PASSWORD` đang dùng `Admin@123` trên VPS | 🔴 Cao | Nếu VPS đang chạy với `.env` chưa đổi, sau khi deploy với `SPRING_PROFILES_ACTIVE=prod`, backend vẫn start được nhưng admin password vẫn yếu. Cần rotate password thủ công |
| Docker image cũ không có `application-prod.properties` | 🟡 Trung bình | Image cũ trên GHCR không có file này. Cần build và push image mới sau khi merge |
