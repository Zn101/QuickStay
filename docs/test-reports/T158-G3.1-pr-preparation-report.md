### 3.3. Phân tích lỗ hổng: Tại sao chỉ có file CI là CHƯA ĐỦ để ngăn CD deploy khi test hỏng?

> ⚠️ **PHÁT HIỆN LỖ HỔNG QUY TRÌNH NGHIÊM TRỌNG:**

1. **CD chạy hoàn toàn độc lập với CI:**
   - Workflow `.github/workflows/cd-docker.yml` kích hoạt ngay khi có sự kiện `push` lên nhánh `main` (khi merge PR).
   - Nếu `ci-backend.yml` và `cd-docker.yml` nằm ở hai file tách biệt:
     - Khi merge vào `main`, cả hai workflow sẽ **chạy song song độc lập**.
     - `cd-docker.yml` **không hề chờ** `ci-backend.yml` chạy xong.
2. **Dockerfile chủ động bỏ qua test (`-x test`):**
   - Trong `backend/Dockerfile`:
     ```dockerfile
     RUN ./gradlew bootJar --no-daemon -x test
     ```
   - Do đó, dù có test case bị fail trong code, quá trình build JAR và build Docker image vẫn diễn ra trơn tru mà không gặp bất kỳ lỗi nào.
3. **Tự động deploy thẳng lên VPS:**
   - Ngay sau khi build xong Docker image, Bước 7 của `cd-docker.yml` sẽ SSH vào VPS, pull image mới về và restart service.
   - Kết quả: **Code hỏng test vẫn được triển khai thành công lên server production**.

### 3.4. Đề xuất cơ chế chốt chặn an toàn (Quality Gate) 2 lớp

Để ngăn chặn tuyệt đối việc deploy code hỏng lên VPS, đề xuất triển khai 2 lớp bảo vệ:

#### Lớp 1: Khóa phụ thuộc ngay trong Workflow CD (Workflow-level Gate)
Tích hợp bước chạy test trực tiếp vào `cd-docker.yml` trước khi build Docker, hoặc tách job kiểm thử có `needs`:
```yaml
jobs:
  verify-tests:
    name: Run Test Suites Before Build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: "17"
          distribution: "temurin"
          cache: gradle
      - name: Run Backend Tests
        run: |
          chmod +x backend/gradlew
          ./backend/gradlew -p backend test
      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"
      - name: Run Frontend Tests
        run: |
          cd frontend && npm ci && npm test

  build-and-push:
    name: Build & Push Docker Images
    needs: [verify-tests]   # BẮT BUỘC: Test phải pass mới được build & deploy
    runs-on: ubuntu-latest
    steps:
      # ... các bước build, push GHCR và deploy VPS ...
```
*Lợi ích:* Nếu bất kỳ unit test backend hoặc frontend nào thất bại, job `build-and-push` sẽ bị hủy (cancelled/skipped), Docker image không được build, không push lên GHCR và VPS không bị đụng tới.

#### Lớp 2: Cấu hình Branch Protection Rules trên GitHub
- Thiết lập Rule cho nhánh `main` và `recovery/clean-dev`:
  - Bật: **Require status checks to pass before merging**.
  - Chọn check bắt buộc: `Build & Test (Java 17)` và `Build & Test (Node 20)`.
- *Lợi ích:* Ngăn không cho bất kỳ ai (kể cả admin) bấm nút Merge PR nếu test chưa xanh.
