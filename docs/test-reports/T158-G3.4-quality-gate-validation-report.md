## 2. Giai đoạn 2 – Thiết kế và Chuẩn bị Quality Gate

### 2.1. Kiểm tra các workflow hiện có trên repository
- Cả hai nhánh `origin/main` và `origin/recovery/clean-dev` hiện chỉ có duy nhất một file workflow là `.github/workflows/cd-docker.yml`.
- Các file `ci-backend.yml` và `ci-frontend.yml` không tồn tại (đã bị xóa trong chuỗi revert ngày 02/11/2026).
- **Kết luận:** Không có bất kỳ workflow CD độc lập nào khác có thể vô tình bypass Quality Gate. Mọi luồng triển khai đều tập trung tại file `cd-docker.yml`.

### 2.2. Chuẩn bị cấu hình Quality Gate cho `.github/workflows/cd-docker.yml`

Đã thiết kế hoàn chỉnh nội dung file `.github/workflows/cd-docker.yml` bảo đảm đầy đủ 6 yêu cầu kỹ thuật:

```yaml
# ============================================================
# QuickStay – CI/CD: Quality Gate, Docker GHCR & VPS Deploy
# ============================================================

name: CD – Quality Gate & Production Deploy

on:
  pull_request:
    branches:
      - main
  push:
    branches:
      - main

permissions:
  contents: read
  packages: write

jobs:
  # ─────────────────────────────────────────────────────────────
  # CHẶNG 1: QUALITY GATE (BẮT BUỘC TRÊN CẢ PULL REQUEST VÀ PUSH)
  # ─────────────────────────────────────────────────────────────
  verify-tests:
    name: 1. Quality Gate – Run Test Suites & Verification
    runs-on: ubuntu-latest

    steps:
      - name: 1.1. Checkout source code
        uses: actions/checkout@v4

      # --- BACKEND VERIFICATION ---
      - name: 1.2. Set up JDK 17 (Temurin)
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
          cache: gradle

      - name: 1.3. Grant execute permission to Gradle wrapper
        run: chmod +x backend/gradlew

      - name: 1.4. Run Backend Tests (JUnit 5 + H2 in-memory)
        run: ./backend/gradlew -p backend test --no-daemon

      # --- FRONTEND VERIFICATION ---
      - name: 1.5. Set up Node.js 20
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json

      - name: 1.6. Install Frontend Dependencies
        working-directory: frontend
        run: npm ci

      - name: 1.7. Run Frontend Unit Tests (Vitest)
        working-directory: frontend
        run: npm test

      - name: 1.8. Verify Frontend Production Bundle Build
        working-directory: frontend
        run: npm run build

  # ─────────────────────────────────────────────────────────────
  # CHẶNG 2: BUILD & PUSH DOCKER IMAGES (GHCR)
  # Yêu cầu: verify-tests PHẢI THÀNH CÔNG 100%
  # Chỉ kích hoạt khi: sự kiện là PUSH vào nhánh main
  # ─────────────────────────────────────────────────────────────
  build-and-push:
    name: 2. Build & Push Docker Images to GHCR
    needs: [verify-tests]
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest

    steps:
      - name: 2.1. Checkout repository
        uses: actions/checkout@v4

      - name: 2.2. Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: 2.3. Log in to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      # Backend Build & Push
      - name: 2.4a. Extract metadata for backend
        id: meta-backend
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/zn101/quickstay-backend
          flavor: latest=true
          tags: |
            type=sha,prefix=sha-,format=short
            type=raw,value=latest,enable={{is_default_branch}}

      - name: 2.4b. Build and push backend image
        uses: docker/build-push-action@v6
        with:
          context: ./backend
          file: ./backend/Dockerfile
          push: true
          tags: ${{ steps.meta-backend.outputs.tags }}
          labels: ${{ steps.meta-backend.outputs.labels }}
          cache-from: type=gha,scope=backend
          cache-to: type=gha,scope=backend,mode=max

      # Frontend Build & Push
      - name: 2.5a. Extract metadata for frontend
        id: meta-frontend
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/zn101/quickstay-frontend
          flavor: latest=true
          tags: |
            type=sha,prefix=sha-,format=short
            type=raw,value=latest,enable={{is_default_branch}}

      - name: 2.5b. Build and push frontend image
        uses: docker/build-push-action@v6
        with:
          context: ./frontend
          file: ./frontend/Dockerfile
          push: true
          tags: ${{ steps.meta-frontend.outputs.tags }}
          labels: ${{ steps.meta-frontend.outputs.labels }}
          cache-from: type=gha,scope=frontend
          cache-to: type=gha,scope=frontend,mode=max

  # ─────────────────────────────────────────────────────────────
  # CHẶNG 3: DEPLOY TO VPS (BẢO TOÀN NGUYÊN VẸN CẤU HÌNH HIỆN TẠI)
  # Yêu cầu: build-and-push PHẢI THÀNH CÔNG 100%
  # ─────────────────────────────────────────────────────────────
  deploy-to-vps:
    name: 3. Deploy to Ubuntu VPS via SSH
    needs: [build-and-push]
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest

    steps:
      - name: Deploy to VPS
        env:
          VPS_HOST: ${{ secrets.VPS_HOST }}
          VPS_USER: ${{ secrets.VPS_USER }}
          VPS_SSH_KEY: ${{ secrets.VPS_SSH_KEY }}
        run: |
          set -e

          mkdir -p ~/.ssh
          chmod 700 ~/.ssh

          printf '%s' "$VPS_SSH_KEY" | base64 -d > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519

          ssh-keyscan -t rsa "$VPS_HOST" > ~/.ssh/known_hosts
          ssh-keygen -lf ~/.ssh/known_hosts | grep -F "SHA256:fC0vLYUEKoEyoQsLPjKfSwCm1N9fN5g08MRUyKgAgQM"

          ssh -i ~/.ssh/id_ed25519 \
            -o BatchMode=yes \
            -o StrictHostKeyChecking=yes \
            "$VPS_USER@$VPS_HOST" 'bash -s' <<'REMOTE'
          set -e
          cd /opt/quickstay

          echo "Pulling latest QuickStay images..."
          docker compose pull backend frontend

          echo "Restarting backend and frontend..."
          docker compose up -d --no-build --no-deps backend frontend

          echo "Waiting for backend health..."
          for i in $(seq 1 30); do
            if curl -fsS http://localhost:8080/actuator/health | grep -q '"status":"UP"'; then
              echo "Backend is healthy."
              curl -fsSI http://localhost
              exit 0
            fi
            sleep 2
          done

          echo "Backend health check failed."
          docker compose logs --tail=100 backend
          exit 1
          REMOTE
```

## 4. Danh sách rủi ro còn tồn tại

1. **Rủi ro rớt mã nguồn T132–T147 (Nghiêm trọng):** Nhánh `recovery/clean-dev` hiện tại chưa chứa 2 commits `8875090` và `165e4be`. Nếu mở PR vào `main` lúc này, toàn bộ công việc tuần 2 của Minh sẽ bị bỏ sót.

3. **Chưa áp dụng Quality Gate lên remote:** File `cd-docker.yml` trên remote `origin/main` và `origin/recovery/clean-dev` vẫn là bản cũ chưa có job `verify-tests`.
