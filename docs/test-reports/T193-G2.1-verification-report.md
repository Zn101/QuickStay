| `JWT_SECRET` trong prod | Dòng 40: `JWT_SECRET: ${JWT_SECRET}` – **Không có fallback**, đây là cấu hình **đúng**; nếu thiếu biến, docker compose báo lỗi |

**Kết luận R-02 (ADMIN_PASSWORD):** **CONFIRMED**

Nhưng trong `application.properties` dòng 16: `${JWT_SECRET:dev-only-secret-change-me-dev-only-secret-change-me}` vẫn có fallback dev, sẽ được áp dụng nếu ứng dụng được chạy **không qua docker-compose** hoặc biến môi trường bị thiếu.

### 3.3 Port `8080` Backend Mapping ra Host

| Thuộc tính | Bằng chứng |
|---|---|
| `docker-compose.prod.yml` dòng 51-52 | `ports: - "${BACKEND_PORT:-8080}:8080"` |
| `docker-compose.prod.yml` dòng 53 | `networks: - internal` |
| Hậu quả | Dù backend nằm trong mạng `internal`, port 8080 vẫn được bind ra `0.0.0.0:8080` của host (mặc định Docker) |
| Healthcheck VPS trong cd-docker.yml (dòng 143) | `curl -fsS http://localhost:8080/actuator/health` → Healthcheck truy cập qua `localhost:8080`, **không phụ thuộc** vào việc 8080 mở ra host (có thể dùng container-internal URL) |
| Nginx proxy | `proxy_pass http://backend:8080` trong `nginx.conf` → Nginx giao tiếp qua Docker network, không cần 8080 mở ra host |

**Kết luận R-05:** **CONFIRMED** – Port 8080 mở ra host là không cần thiết và làm tăng bề mặt tấn công. Tuy nhiên, healthcheck trong VPS deploy script đang dùng `localhost:8080` trực tiếp, nên nếu xóa port mapping cần cập nhật healthcheck script trong `cd-docker.yml` sang dùng `docker compose exec backend` hoặc URL nội bộ.

> [!IMPORTANT]
> **Phụ thuộc quan trọng phát hiện mới:** Bước `Deploy to VPS` trong `cd-docker.yml` dòng 143 dùng `curl -fsS http://localhost:8080/actuator/health` để kiểm tra sức khỏe backend sau khi restart. Nếu xóa port mapping `8080:8080` khỏi `docker-compose.prod.yml`, lệnh này sẽ **thất bại** vì host không còn truy cập được port 8080. Cần thay đổi đồng thời cả `docker-compose.prod.yml` và bước healthcheck trong `cd-docker.yml`.

### 3.5 Demo Mode và Token Exposure

| Hạng mục | Bằng chứng |
|---|---|
| `ForgotPasswordResponse` | Trả về `demoEmail` (chứa `bodyHtml`) khi `demoMode=true` |

> [!CAUTION]
> **R-09 (MỚI) – Information Disclosure: Reset Token lộ trong API Response (Medium-High)**  
> Khi `MAIL_HOST` bị bỏ trống hoặc SMTP thất bại, endpoint `POST /api/auth/forgot-password` trả về response JSON chứa `demoEmail.bodyHtml` với reset token đầy đủ cho bất kỳ CUSTOMER account nào. Nếu production VPS thiếu cấu hình `MAIL_HOST`, người dùng (hoặc attacker) có thể lấy token đặt lại mật khẩu trực tiếp từ API response thay vì nhận qua email.

## Phần 6 – Danh sách Công việc Cần Trưởng nhóm Phê duyệt

Các hành động sửa chữa sau **CẦN được Trưởng nhóm phê duyệt trước** vì có thể ảnh hưởng pipeline hoạt động và cấu hình VPS đang chạy:

| STT | Hành động | Lý do cần phê duyệt |
|---|---|---|
| 1 | Đưa `ci.yml` lên nhánh `main` với trigger `push`+`pull_request` | Thay đổi pipeline chính, ảnh hưởng quy trình merge của toàn nhóm |
| 2 | Cập nhật `cd-docker.yml` để CI pass là điều kiện tiên quyết | Thay đổi CD có thể chặn deploy nếu test fail |
| 3 | Bật Branch Protection Rule trên nhánh `main` (required status checks) | Ảnh hưởng quyền push trực tiếp vào `main` của tất cả thành viên |
| 4 | Xóa fallback `:-Admin@123` trong `docker-compose.prod.yml` và xác nhận `.env` trên VPS đầy đủ | Thay đổi file production; sai sót có thể khiến service không khởi động |
| 5 | Xóa port mapping `8080:8080` trong `docker-compose.prod.yml` và sửa healthcheck script trong `cd-docker.yml` | Phải thực hiện đồng thời 2 file để tránh healthcheck VPS thất bại |
| 6 | Nâng cấp `vitest` lên `5.x` (breaking change) và `react-router-dom` lên `7.x` (breaking change) | Có thể gây xung đột API test và route; cần kiểm thử toàn diện trước |
| 7 | Xử lý demo mode token exposure (`R-09`) trong `AuthService.java` | Thay đổi logic nghiệp vụ auth; cần xem xét kỹ |
| 8 | Cung cấp GitHub PAT có scope `security_events` để kiểm tra Dependabot/Code Scanning | Quyền truy cập bảo mật của repository |
