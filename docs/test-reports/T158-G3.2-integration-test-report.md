## 3. Đánh giá chi tiết các hạng mục kiểm thử

### 3.1. Hạng mục Backend
- **Cấu hình Java 17 & Gradle:**
  - Gradle wrapper hoạt động tốt với JDK 17 tại đường dẫn `C:\Program Files\Java\jdk-17`.
  - Quá trình biên dịch mã nguồn (`:compileJava`, `:processResources`, `:classes`, `:compileTestJava`, `:testClasses`) hoàn toàn sạch, không có cảnh báo hoặc lỗi cú pháp.
- **Hiện tượng lỗi bộ nhớ ảo (Paging File):**
  - Khi chạy toàn bộ test suite lớn (271 test cases), Gradle mặc định fork nhiều tiến trình `Gradle Test Executor` song song, mỗi tiến trình yêu cầu phân bổ 512MB RAM thực/ảo.
  - Hệ thống Windows gặp lỗi `DOS error 1455: The paging file is too small for this operation to complete` khi cấp phát bộ nhớ ảo (G1 virtual space allocation).
  - *Giải pháp đề xuất khi chạy local:* Thêm tham số giới hạn fork và heap trong lệnh chạy:
    ```bash
    backend\gradlew.bat -p backend test -Dorg.gradle.workers.max=1 -Dorg.gradle.jvmargs="-Xmx512m -XX:+UseSerialGC"
    ```
  - Trên GitHub Actions runner (Ubuntu VM có swap 4GB+), hiện tượng này không xảy ra.

### 3.2. Hạng mục Frontend
- **Kết quả Vitest:**
  - `18/18 PASSED` (100% test thành công, 0 failed, 0 skipped).
  - Đã xác thực thành công các luồng UC05 (Hotel Detail, Date Validation, Room List) và UC06 (Booking Form, Dynamic Total Price Calculation).
- **Kết quả Build Production:**
  - Vite v5.4.21 đóng gói production bundle thành công trong 4.29s.
  - Tổng kích thước tối ưu: Bundle JS 333.61 kB (gzip 90.55 kB), CSS 69.44 kB (gzip 10.92 kB).
- **Cấu hình Nginx:**
  - File `frontend/nginx.conf` thiết lập đầy đủ reverse proxy `/api/` trỏ tới `http://backend:8080`, timeout 60 giây, truyền đủ headers `X-Forwarded-For`, `X-Forwarded-Proto`.
  - Hỗ trợ định tuyến Single Page Application (SPA): `try_files $uri /index.html`.

### 3.3. Hạng mục Docker & Production Compose
- **docker-compose.prod.yml:**
  - Cấu hình chuẩn cho môi trường production:
    - Service `mysql`: dùng image `mysql:8.4`, cấu hình biến qua `.env`, volume `mysql_prod_data`, không mở cổng 3306 ra Internet.
    - Service `backend`: dùng image `ghcr.io/zn101/quickstay-backend:latest`, biến môi trường liên kết nội bộ `mysql:3306`, healthcheck qua `curl http://localhost:8080/actuator/health`.
    - Service `frontend`: dùng image `ghcr.io/zn101/quickstay-frontend:latest`, lắng nghe cổng HTTP chuẩn.
- **An toàn dữ liệu:**
  - Không có bất kỳ lệnh xóa hoặc ghi đè volume MySQL nào được thực hiện.
  - Không có kết nối tới VPS thật trong suốt quá trình kiểm thử.

## 4. Kiểm tra quy trình CI/CD & Đề xuất Quality Gate

### 4.1. Đánh giá rủi ro hiện tại
1. `ci-backend.yml` và `ci-frontend.yml` vẫn đang bị xóa khỏi repository.
2. File `backend/Dockerfile` sử dụng `-x test`:
   ```dockerfile
   RUN ./gradlew bootJar --no-daemon -x test
   ```
3. File `.github/workflows/cd-docker.yml` trên `main` kích hoạt ngay khi push vào `main`, sau đó tự động SSH vào VPS để pull và restart container:
   - Nếu ai đó merge một commit bị vỡ test vào `main`, CD vẫn build ra image Docker bình thường và deploy thẳng lên VPS production!

### 4.2. Thiết kế Quality Gate đề xuất (Thêm `verify-tests` vào CD)

Để bảo vệ VPS production mà vẫn giữ nguyên được các secrets, SSH key và GHCR namespace đã cấu hình của `main`, giải pháp tối ưu là chèn thêm job `verify-tests` làm điều kiện tiên quyết (`needs: [verify-tests]`) ngay trong `.github/workflows/cd-docker.yml`:

```yaml
name: CD – Build & Push to GHCR & Deploy VPS

on:
  push:
    branches:
      - main

permissions:
  contents: read
  packages: write

jobs:
  # ── BƯỚC 0: CHỐT CHẶN KIỂM THỬ BẮT BUỘC (QUALITY GATE) ──
  verify-tests:
    name: Run Test Suites Before Build
    runs-on: ubuntu-latest
    steps:
      - name: Checkout source code
        uses: actions/checkout@v4

      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
          cache: gradle

      - name: Grant execute permission for Gradle wrapper
        run: chmod +x backend/gradlew

      - name: Run Backend Unit & Integration Tests
        run: ./backend/gradlew -p backend test --no-daemon

      - name: Set up Node.js 20
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json

      - name: Run Frontend Tests
        run: |
          cd frontend
          npm ci
          npm test

  # ── BƯỚC 1: BUILD, PUSH GHCR & DEPLOY VPS (CHỈ CHẠY KHI TEST PASS) ──
  build-and-push:
    name: Build & Push Docker Images
    needs: [verify-tests]   # BẮT BUỘC: Test phải xanh thì mới chạy build & deploy!
    runs-on: ubuntu-latest
    steps:
      # ... Giữ nguyên toàn bộ các bước buildx, login GHCR, metadata, build-push ...
      # ... Giữ nguyên 100% Bước 7 Deploy to VPS qua SSH ...
```
